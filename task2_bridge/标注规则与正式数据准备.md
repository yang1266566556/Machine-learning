# 桥面裂缝标注规则与正式数据准备

## 当前结论

五张小图已经完成首轮人工标注，说明工具操作已掌握；现有标签属于待修订初稿。
这些图来自同一张原图，不构成正式训练、验证、测试数据集。当前不启动训练，不要求反复做工具练习。
本说明给出规则草案；裂缝与灌缝修补的类别边界仍需核实，不能将所有深色条带自动视为裂缝。

## 目标与类别边界

- 主任务：无人机照片中桥面沥青路面的可见裂缝区域分割。
- crack：可确认的可见裂缝面积，沿实际边界描绘，不额外加粗。
- 背景：确认不属于目标的正常路面、标线、阴影、接缝以及已确认的修补区域等。修补区域内如果存在新的可见裂缝，仍需单独判断。
- 待确认：仅凭图像不能区分裸露裂缝、灌缝和修补的区域。先记录图片名与位置，不强行判成 crack 或背景；这类图片审核前不进入正式训练。
- 不推断被标线、车辆或阴影完全遮住的裂缝，不从照片推断物理宽度或结构安全等级。

## 画法：直接执行

1. 用多边形画面积，沿一侧走到末端，再沿另一侧返回闭合。不要用单条中心线代替面积。
2. 在转弯、宽度变化处增加顶点；直线段无需密集点。不要靠增加点数掩盖边界判断不准。
3. 主干和复杂分支分别画，多边形统一标 crack，连接处可少量重叠；转换时合并同类区域。
4. 不允许轮廓自交，不允许大三角圈入正常路面。贴着可见边界，不把周围暗色纹理一起包入。
5. 正式小图内所有清晰目标都需覆盖。连续可见裂缝不能人为断开；真正不连续或被遮挡的部分不能脑补连接。
6. 裂缝延伸到裁图边界时，标到图像边界，不为方便而提前截断。
7. 保存同名 JSON；保留 PNG 和 JSON。任何批量转换前保留原始标注，不覆盖。

## 每张图的验收标准

- 图片和 JSON 一一对应，尺寸一致；类别为 crack，形状为 polygon，坐标有效。
- 没有自交或退化轮廓。程序几何检查通过仅代表相应检查项通过，不保证语义正确。
- 对照原图开关标注，检查漏标、圈多、断点、分支和图像边缘。
- 不确定区域有记录并完成审核；未经确认的图片不能作为已完成负样本或可靠真值。
- 完好路面可保留为空标注负样本，但必须明确人工确认过；不能把缺少 JSON 当作没有裂缝。

## 对现有五张的处理

无需整批删除或重画；后续按检查图集中修正。自动检查不擅自改动顶点。

## 正式数据的准备顺序（尚未执行）

1. 核对 55 张原图的拍摄视角和相同桥面区域，建立物理区域分组。文件不同不代表场景独立。
2. 从至少 12 张原图选取满足课程要求的样本，覆盖简单/分叉/网状裂缝、不同光照、标线、修补等情况，同时选确认的完好路面。
3. 先按物理区域安排训练、验证、测试，再从各组裁图。同一桥段的重复视角、相邻或重叠裁图不能跨集合。若没有足够独立区域，应先报告限制并调整数据方案。
4. 裁图保持原始像素，初始 512×512；保存原图文件名、坐标、组别、审核状态。具体数量在试标耗时、分组结果和类别规则确认后制定，不凭空规定。
5. 测试数据要保留代表性的完整场景，不能只挑容易的裂缝；训练样本可针对难例适当补充。
6. 完成标签审核后转换掩膜并检查对齐，再进行少量数据的训练流程验证，最后正式实验。
